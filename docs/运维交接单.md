## 4. 改代码 + 上线(需要工程)

1. 在本机 `Projects/BA-repo` 改 `index.html`(整个 app 就这一个文件)。
2. 提交并推送:
   ```bash
   git add index.html
   git commit -m "说明改了什么"
   git push origin main
   ```
3. 推上去后 GitHub Pages **约 1–2 分钟**自动上线。
4. **验证**:硬刷新线上网址,确认你改的东西真的出现了(不要只看「推成功」,要看内容)。

> 整个前端是**单一文件** `index.html`(约 54 万字,7400 行)。没有打包/编译步骤,改完直接推。

## 5. 改数据库(需要工程)

- 在 **Supabase → SQL Editor** 跑 SQL。
- **规矩(重要):每改一次数据库,就在 repo 的 `migrations/` 存一个编号档**(`NNN_说明_日期.sql`),写清楚什么时候跑、为什么、改了什么。跑过的档不要再改,要改开新编号。
- `migrations/README.md` 有完整规则;`migrations/checks/` 放只读体检查询(如 RLS 安全盘点)。
- **写入模型**:网页不直接写表,都走后端函数(security definer + PIN 验证)。所以新加表时要:① 不给公开角色写权限 ② 个资类表要开 RLS、只走函数读。详见 `migrations/checks/rls_audit.sql`(能一键盘点安全状态)。

## 6. 备份与还原

- **自动备份**:每天 **21:00**,在 Aj. Tsai 的 Mac 上由系统排程(launchd)自动跑,把整库每张表存成快照,放在该机 `~/CICBA-backups/`。
- **风险**:只在那一台 Mac 上。机器关机/那天没开 = 当天没备份(改进项:加一条云端排程备份)。
- **随手备份**:任何人都能在网站右上「**导出 JSON**」下载一份当下数据。
- **还原**:从备份档把数据写回 Supabase(用对应的表)。不熟的话先联络第 9 节的人,别直接覆盖线上。

## 7. 常见故障与排查

| 症状 | 多半原因 | 处理 |
|---|---|---|
| 看到旧版、改动没出现 | 浏览器缓存 | **硬刷新**;还不行等 1–2 分钟再刷(Pages 部署中) |
| 后台操作「操作失败」 | 看真实报错那句 | 抄下整句;若是 `permission denied` / 列不存在之类 → 找工程 |
| 新增届别/老师报错 | 曾因 audit_log 列冲突(已修,见 `migrations/001`) | 若再现,参照 001 的说明 |
| 想确认数据库安全没破 | — | 跑 `migrations/checks/rls_audit.sql`,看「结论」栏有没有 ⚠️ |
| 某老师离职了还在选单 | 该用「离职」而非留着 | 后台→老师库→离职 |
