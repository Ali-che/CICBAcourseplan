## 1. 它是什么
新分页「课表制作」：
选学期 → **⚡一键自动排** → **上/下半两张网格**（周几 × 上午/下午 × 教室）→ 冲突/超容量/超门数/超学分 **即时标红** + 侧栏列问题 → **手动拖课片微调**（即时重算）→ **💾存档** + **🖨️列印**。
> 本质是一个**排课求解器**：不保证完美解；排不下的**留空标红**让人手动，不硬塞、不假装排好。

## 2. 权限
- **能排 / 存 / 列印**：Head of Administration（角色码 `teacher`）＋ Admin。
- **只读看 + 列印**：Director / pic / 其他。
> 与「秘书处对账」一致由少数人掌控；秘书处正是排教室的人。

## 4. 时段模型（2026-11-15 更新，见 §11）
- 周一~周五 × { `am` 09:00–12:00、`pm` 13:30–16:30 }。**每门课一周 2 节、各 3h**，优先分散到不同天。
- **网格**：周一~周五固定 + **周六/周日「用到才显示」**（`TT_WEEKDAYS` + `anySat/anySun`）；周日列留给手动拖。
- **Capstone**：当**普通 2 节课**排，但**只排周末**，各 3h——**周五/周六优先**（匹配 aSc：如 KG133/BA103 周五六上午、KF412/KL412 周五六下午），**排不下才用周日**（2026-11-15 定）。**不再**「周五上下午单格、周六只给 Capstone」的旧写法。

## 5. 排课规则
> ⚠ **本节是 2026-11-13 的最初设计，已过时，留作历史记录。** 现行规则见 `docs/课表制作_排课规则说明.md`。
> 主要差别：下面 5.1 的第 6–8 条（老师每半≤4 门、届别 4+3、学分≤21）现在是**软提醒**（可勾「已核对」放行），不是硬约束；Capstone 改为周末一天三个时段（§11.2i）；备注改用「排课要求」栏位（§11.11）。
### 5.1 硬约束（违反标红，不硬塞）
1. 教室容量 `cap` ≥ 课人数。
2. 一时段一教室一门课。
3. 一时段一**老师**不排两门（老师不撞堂）。
4. 一时段一**届别**不排两门（按 cc 每个 cohort；届别不撞堂）。
5. **Capstone** → 下半 · 当普通 2 节课排在**周末（周五/周六）**，各 3h（`TT_CAP_DAYS`，第二节经 `_ttFindSecond` 按 isCap 选周末日）；识别靠 `type==='Capstone'`，不写死课码。
6. **老师每半 ≤ 4 门**。
7. **届别每半 4+3 或 3+4**（每届别上/下半门数为 {4,3} 或 {3,4}）；**有 Capstone 则该届别总门数 ≤ 6**。
8. **届别每学期总学分 ≤ 21**（学分=`catalog.credit`；Capstone=6 学分）。
### 5.2 软优先（尽量满足，冲突可让）
- **321/322 优先给 CD 专业课**（`pref_dept` 匹配课的 dept）。
- **LA/KH 层级排序**：同学期开了**连续两级**（如 LA130&LA131、LA131&LA132、KH351&KH352…）→ **低级排上半、高级排下半**（先修低级）；单开一门不强制。
### 5.3 上下半分配
- 排课表**已填 `half`（上/下）的 → 钉死，照用**。
- `half` 空/全学期的 → **系统自动分**（满足约束 6/7/8 + LA·KH 排序）。
- 系统**可在可行时把未钉死的课在上/下半间挪动**，以解掉冲突、配平门数/学分（Aj. Tsai 确认可调）。
### 5.4 求解策略
贪心 + 回溯/局部搜索皆可；目标：满足全部硬约束，软优先尽量。**排不下的留空标红**，列侧栏让人手动拖。

### 5.5 备注（`nt`）当约束读（Aj. Tsai 确认）
排课记录的**备注里常写排课的特殊要求，要当约束遵守，不能忽略**（例：固定某时段/星期、指定某教室、合班、要大教室或视听设备等）。
- 备注是**自由文字**，实作时**先从实际资料捞一批 `nt` 样本**（`sget('schedule?select=note&sem=eq.<学期>')` 或排课表现成 `schD` 的 `nt`），归纳出能自动遵守的类型（如「周三」「下午」「X教室」「合班」关键词），把这些变成排课时的额外约束。
- **抓不出规则的随意备注**：不猜、不乱排 → 把该门课连同原始备注**列到侧栏「备注待人工」**，让排的人自己照办。
- 备注原文也要能在课表/格子看到（别弄丢），方便人工核对。
> ⚠ 开工后请 Aj. Tsai 给几个真实备注例子，好把「能自动遵守的类型」定准。

## 11. 2026-11-15 大改与优化建议（以本节为准，覆盖上文旧描述）

### 11.1 已上线的交互（分支 `courseplan-b040ee` → `main`，已部署并比对 hash 验证）
- **点课片 → 弹窗「编辑这一节」**：三视图（依教室号/依届别/依老师）点任一课片，弹窗可改 **授课老师 / 教室 / 周几 / 时段**，套用即时重算标红。点击 vs 拖拉用 **mousedown→mouseup 位移**区分（<6px 算点击）——人手点击常带微移、原本 `onclick` 会被当拖拽吃掉，故改此法。
- **红框原因**：点红框课片 → 弹窗顶部红字列出冲突（**同教室撞堂 / 老师撞堂 / 届别撞堂 / 超容量** + 具体时段与对手课）；`_ttConflicts` 记 `_ttBadWhy`，也写进 `title`。
- **拖拉微调**：每节课片可单独拖到别格/别教室；未排课做成**可拖胶囊**（带 **上半/下半/全** 色标），底部总表 + 每张届别/老师卡片内都能拖进去。拖进去时第二节同教室排不下会退用别间够大教室。
- **写回排课表**：「↩ 写回排课表(上下半+老师)」把课表里的 **上下半 + 老师** 差异写回 `schD`（`updateRecord`，逐门确认）。注：改老师只在课表这份，按此钮才回写；再「一键自动排」以排课表为准。
- **依教室号已压缩**：格子只留「人数·课码·老师」，长串届别收进 hover；教室栏 `position:sticky`（右拉不丢）；cell `max-width:150px`。
- **课片浮出卡**（`_ttTipShow`/`_ttTipBind`，三视图通用，取代原生 `title`）：鼠标一到就浮出「课码·总人数·教室／老师·专业／**届别明细（每届人数，取自 `schD.cc`）**／备注／标红原因」。选浮出而非弹窗，因为点击已用于「编辑这一节」。只读角色点一下也会显示（触控没有 hover）。
- **工具列 + 视图切换 sticky**：滚动时「尚未存档/⚡一键自动排/存档/列印/写回 + 依教室号/届别/老师」整块贴在站点头下不消失。
- **Capstone 老师周五**：教 Capstone 的老师，周五不排别的课（`_capFriTc`，留给周末 Capstone）。

### 11.2 时段 / Capstone 修正（配合 §4、§5.1-5）
- 时段维持上午/下午；网格周一~五 + 周六/周日「用到才显示」。
- Capstone 当普通 2 节课排**周末（周五/周六）**，识别靠 `type==='Capstone'`（**不写死 KG133——各专业 Capstone 课码不同**，见 §3.1）。

### 11.2b 一键自动排重写（2026-11-15，Aj. Tsai「不够聪明」）
旧版：只排一遍、先到先得、**两节必须同一间教室都有空才排**、教室先看到哪间用哪间。新版（`_ttSolve` + `_ttRunOnce`/`_ttFindSlots`）：
1. **两节各自挑（时段，教室）**：同一间优先（不同间加罚分），但不再因为「同一间没有 2 个空档」就排不下。
2. **教室挑刚好够大的**（`_ttCandRooms`）：大教室留给大班；CD 课仍优先 321/322，其他课最后才用。
3. **排不满就挪课**：先整门挪走一门挡路的课（对方也要能重新排满，否则还原）。
4. **改善间隔**：两节同一天/连续两天的课，先试「两门课各换一节」，再试整门挪；两门合计间隔变好才接受。
5. **多试 40 + 8 种先后顺序**（固定乱数种子 → 同样的排课每次结果一样），留分数最低的一版。计分：未排最重（大班没排更重）＞只排 1 节＞间隔不理想/两节不同教室。
   - 前 40 种（`TT_SOLVE_TRIES`）按「抢人程度」排先后：每个届别在该半还有几门别的课 + 老师还有几门别的课 + 可用教室少。
   - 后 8 种（`TT_SOLVE_TRIES_COH`）按「**届别数最多的先排**」（Aj. Tsai 2026-11-15 提议）。实测单用这条规则略差（2569-1 未排 3 对 2、2569-2 未排 8 对 7），因为届别数没算每届有多忙、也没算老师；但作为额外尝试加进来不会让结果变差。目前三个学期加入前后结果相同，耗时多约 0.15 秒。
   - 同一实验的另一个结论：只排 1 遍 vs 试多种顺序的差距（3→2、10→7）大于两条排序规则之间的差距，多试比换规则有效。
6. **改半建议**：排课表写死上/下半、却排不满的课，算「改到另一半能不能排满」；只给建议与「↪ 照此改到下半」钮（`ttApplyHalfHint`，改的是课表，要同步排课表再按写回），不擅自改。
7. 「详情与建议」新增「只排到 1 节 N 门」清单。
8. 顺带修：备注解析把课码数字（`LA161=LA131`）和日期（`1113`）当成教室号 → 现在只认明写「教室/lab NNN」或独立出现的库内教室号，其余含数字的备注列人工核对；「Capstone 老师周五不排别课」收窄到该老师有 Capstone 的那一半。

实测（同一份数据，旧版 → 新版）：

| 学期 | 未排 | 只排 1 节 | 一般课两节同一天 | 耗时 |
|---|---|---|---|---|
| 2569-1 | 6 → 2 | 0 → 0 | 11 → 7 | 约 0.6 秒 |
| 2569-2 | 11 → 7 | 2 → 0 | 6 → 4 | 约 0.7 秒 |
| 2569-3 | 1 → 0 | 0 → 0 | 4 → 0 | 不到 0.1 秒 |

三个学期都验证：无撞堂、教室容量够、一般课不在周末、Capstone 不在平日、重复执行结果一致。
**仍有的限制**：届别在某半有 5 门课（10 格全满）且课之间届别交错时，还会剩几门两节同一天（多为周五上下午）；2569-2 剩的 7 门未排里 2 门是 Capstone 老师超载、其余是届别/老师时段真的不够（见容量预检）。判撞堂仍是「同届别一律不准同时段」，尚未按人数放宽（§11.4-6）。

### 11.2c 备注照办、专用教室、版面（2026-11-15，Aj. Tsai 实测后提的 5 点）

### 11.2f 还原／重做（2026-11-15）
- **做法**：每个会改课表的动作开头先 `_ttUndoPush()` 记下当时的课表快照（`_ttSnap`：`sol` + `dirty` 的 JSON 字串；求解用的 `_` 开头暂存栏位不记，`manualNotes` 只记 id、还原时接回同一个物件）。已接：拖进教室网格（`_ttDrop`）、拖进依届别/依老师网格（`_ttDropEntity`）、弹窗保存（`_ttCellSave`）、加一节（`_ttAddSession`）、移回未排（`_ttUnplaceCourse`）、照建议改半（`ttApplyHalfHint`）、一键自动排（`ttAutoSolve`）。**以后新增会改课表的动作，一律在开头加 `_ttUndoPush()`。**
- **操作**：`Ctrl+Z`／`⌘Z` 还原，`Ctrl+Y`／`⇧⌘Z` 重做（`_ttKeyBind`：只在「课表制作」分页、可编辑角色生效；焦点在文字输入框时让给输入框自己的还原）。工具栏有「↶ 还原」「↷ 重做」钮（有记录才出现，没得还原时变淡）。最多 50 步（`TT_UNDO_MAX`）。
- **细节**：没改到东西的步骤（例：拖回原格）还原时自动跳过；还原时会关掉开着的弹窗。
- **限制**：只在这次打开页面期间有效；换学期／重新载入会清空。「💾 存档」「↩ 写回排课表」是写进数据库的，还原不了（存档后仍可把画面上的课表还原到存档前的步骤，再存一次才会覆盖）。
- 顺手修：「待处理一览」的备注改按 id 对回现在的课（未排的课拖进网格后会换成新物件，原本备注区看到的是旧状态）。
- 实测（本地，匿名只读载入，2569-2）：自动排／拖一节／弹窗改时段／移回未排，各自还原后与之前的快照逐字相同、重做后与改动后逐字相同；`⌘Z`、`⇧⌘Z`、`Ctrl+Z`、`Ctrl+Y` 都生效；文字输入框内、其他分页、只读角色不触发；60 步只留 50；换学期后记录清空。

### 11.2g 合班算一门（2026-11-15，Aj. Tsai 确认事实后做）
> ⚠ **同日傍晚已改（见 11.2i）**：Capstone 不再整组合班，只剩「2 人以下的小课跟班」。本节关于 Capstone 的规则与实测数字是当时的版本，备注写「合班」的一般课仍照本节。
- **事实**（Aj. Tsai 确认）：同一位老师的 Capstone 同班级编号（例 Capstone-971 的 BA103、DI325、KL412）是同时间、同教室一起上；备注写「合班」的课（例 IT393+IT262）也是。
- **规则**（`_ttMergeGroups`，在求解一开始、分上下半之前）：**同一位老师**，且
  - Capstone：班级编号相同 → 一组；
  - 非 Capstone：备注含「合班」且排课表的上下半相同 → 一组。
  - 一组只有 1 门就不合并（例 2569-3 的 IT369）。老师待定的不合并。
- **合班后的课**：`id/course/cls` 取组内人数最多的那门，另带 `members=[{id,course,cls,count,cohorts,credit,nt}]`；届别=联集；**人数=各届别取组内最大值再加总**（同一批学生修两个课码只算一次：Aj. Xu 的 971 组直接相加 111、去重后 70；IT393+IT262 是 11 不是 21）。备注合并后重新解析。
- **其他地方跟着改**：显示名 `_ttCC`/`_ttName` 把课码用「+」连起来（`KG133+KF412+FA401-Capstone-971`），课片内可换行；浮出卡列出组内各门与人数；蓝色说明框多一行「🔗 合班 N 组」；学分提醒（>21）逐门算到各自的届别；「写回排课表」逐门写回；漂移侦测逐门比对；存档把 `members` 一起存（存档是整包 JSON，不用改数据库），载回时带回。搬物件的地方（未排⇄已排、还原快照）都带着 `members`。
- **实测**（本地，匿名只读载入）：

  - 2569-3：没有可合并的组，结果不变。
  - 三个学期都 0 撞堂；组内课程数加总 = 排课表笔数（没有课被吃掉）；存档→载回后分组与提醒一致、漂移 0 改 0 删。

### 11.2h 个别学生不挡排课 + 改半方案（2026-11-15）
起因：参考外部排课方案（改 7 门上下半做到 0 老师/班级冲突，个别学生交秘书处理）。试算发现我们卡住的主因是「只有 1 个学生的届别」也被当成不能撞。

### 11.2p 「拆开两节同天」开关：挪开挡路的课、整个时段对调（2026-11-16，已上线 `a8344c5`）

Aj. Tsai 要求把 11.2o 剩下那 2 门也拆开，并做成工具栏的打勾开关（像「个别学生不挡排课」）。

- **开关**：工具栏「☑ 拆开两节同天」（`_ttDeepOn`／`ttDeepToggle`，记在本机 `cic_tt_deep`，**默认开**）。切换会重排（可按「↶ 还原」退回）；跟「个别学生不挡排课」一样，重排会回到排课表原本的上下半。
- **只在排完还剩同天课时才跑**（`_ttDeepFix`，在 `_ttSolve` 套用最好的一版之后跑一次；最多 6 秒 `TT_DEEP_MS`）。平常没有同天课 → 多花 0 毫秒。
- **第一招：挪开挡路的课**（`_ttDeepOne`）：同天课想去的别天时段，看谁占着（同一半、时间重叠）→ 先试拿开一门、再试两门一起拿开，同天课先挑不同天的两格，被拿开的课再重排（两种先后都试）。
- **第二招：整个时段对调**（`_ttDeepSwap`）：把同天课其中一节所在的时段，跟别天的一个时段**连同里面所有的课整批对调**（同一半学期）。同一时段里的课本来互不相撞，整批搬过去也不会撞；每门课都要能去那一天（Capstone 不动、Capstone 老师的课不进周五、备注限定周几）、教室排得开（先用原教室）才成立。16 种对调里挑合计扣分最少的。

- **接受条件（两招都一样）**：每门都排满 2 节、都不同一天、合计扣分变少；否则全部放回原位。
- **改半方案**：找方案时不跑（`_ttSolve(…,{deep:false})`，只看排不排得上，免得变慢）；定案那一版如果有同天课，再整张求解一次带加深搜寻。
- **画面**：课表检查色块多一行「「拆开两节同天」这次拆开了 N 门（…）：做了哪些挪动」；还剩拆不开的，橙框旁写「已试过挪开挡路的课、整个时段对调，仍拆不开」；开关关着且有同天课时提示可打勾再试。`sol.deep={fixed,left,steps,ms}`。
- **实测**：
  - 一键自动排（三学期）：本来就 0 门同天，开关开或关结果一样、时间一样。
  - 2569-2 改半方案（KB222、LA130 上半→下半）套用后：两节同一天 **2 → 0**，73 门全排上、撞堂 0、个别学生撞课 29 → 28 节；做法＝「下半 周五下午 ↔ 周四下午」整个时段对调（5 门课跟着换），多花 10 毫秒。代价：那 2 门变成周四下午＋周五上午（连续两天）。改半方案总时间约 47 秒（原 45 秒）。
  - 随机压力测试（2569-1、2569-2 各 18 种随机改半、少量尝试次数）：36 种里 5 种出现同天课共 9 门，拆开 4 门（2 种全拆开、1 种拆一部分、2 种拆不开）；**没有任何一种出现撞堂、多出未排、少排一节**；加深搜寻最多 35 毫秒。
  - 开关切换、重排、还原正常；375px 溢出 0；ui_smoke 12/12。
- **做不到的**：不保证每种情况都拆得开（压力测试约拆开一半）；拆不开的照样橙框标出，由人决定。

### 11.2r 列印量字留余量（2026-11-16，已上线）
起因：11.2q 末段发现 `tt_print_check 2569-2` 只过 8/11（三种「全部」印法有课片截字）。
- **原因**：送印前量字（`_ttPrintFitText`）是照整张纸的可印宽 1047px 排版来量，一点余量都没有。实测 2569-2：纸面宽 1046px 不截字，1044px 就有 4 片截字，1032px 有 8＋4＋4 片。检查工具量的时候画面多一条 15px 的卷轴（表格宽 1032px），所以报截字。
- **线上实际列印**：Chrome 印 A4 横向的可印宽是 1046.9px，照上面的量测应该不截字，但只差不到 3px（约 0.8mm）；没有逐页看 PDF 确认。先前回报「线上印也会截字」说得太满，更正为「差一点就会截字」。
- **修法**：新常量 `TT_PRINT_SAFE=24`，量字时把纸宽当成 1023px（窄约 6mm）。印表机边界、浏览器、字体宽度有一点出入也放得下。实际印出来的版面宽度不变。
- **代价**（2569-2）：多几片要精简届别。页数、最小字号不变。

| 2569-2 | 并成「个别 N 人」 | 截短 | 页数 |
|---|---|---|---|
| 依教室号·印届别 | 38 → 42 片 | 14 → 17 片 | 6（不变） |
| 依授课老师 | 24 → 30 片 | 6（不变） | 17（不变） |
| 依教室号·不印届别、依届别 | 0 | 0 | 不变 |

- 实测：本机在 1047、1032、1026、1023px 四种宽度量四种印法都 0 截字（1020px 开始各有 2 片）；`tt_print_check` 2569-1／-2／-3 各 11/11；ui_smoke 12/12。没测到：印成纸、Chrome 以外的浏览器。
- **以后**：改列印样式后，除了跑 `tt_print_check`，新增的版面量测一律用 `TT_PRINT_W-TT_PRINT_SAFE`，不要照整张纸宽量。

### 11.2t 课表 ↔ 排课表「双向同步」：随时比对、逐门选方向（2026-11-16，已上线 `9150050`）
Aj. Tsai：「反正就是要相同、双向同步（你建议）」。采用的做法＝**不自动同步，但任何不一样都看得到、每一处一键对齐**。不做全自动的原因：主任不能存档（自动重排没人看、也存不了）；自动写回会不经确认改掉官方排课表。
- **谁说了算**：课程／届别／人数／备注／新增／删除 → 排课表；时段／教室 → 课表；**老师、上下半两边都能改** → 由人逐门选方向。
- **比对补齐**（`_ttDriftFields`）：原本只比课程／老师／届别／人数，现在加 **上下半**（排课表有明写而课表排在另一半才算；排课表留空＝交给系统分，不算；Capstone 与全学期制的学期不比）、**备注**。
- **随时比对**（`_ttDrift(sem,sol)`）：原本只在「看存档、且没有未存改动」时比；现在拿画面上这份课表比（含没排上的课），所以课表上改了老师、套用改半方案还没写回，也会出现橘色框。标题：看存档时「存档 vN 后…可能过时」，其他时候「课表与排课表有 N 处不一样」。刚自动排完＝0 处、不出框。
- **橘色框每一门**写成「栏位：课表 X ／ 排课表 Y」。老师／上下半不一样的那几门，右边两颗钮：

- **「🧩 只补排」的行为跟着改**：老师、上下半不一样的**不动**（原本老师一律改回排课表的），留在橘色框让人逐门选；只处理排课表说了算的那几类。绿色摘要框分列「改成排课表的」与「没动、见橘色框」。锁定判断多看备注（备注改了 → 重新检查原位合不合新备注）。

- **排课表那一页的横幅**（同日加，`#sch-tt-bar`／`_schTtRefresh`／`gotoTt`）：排课表所选学期有课表存档、且跟排课表不一样 → 筛选栏上方橘色横幅「📋 课表制作还没跟上：<学期> 的课表存档 vN 跟排课表有 N 处不一样（内容不同 a 门 · 不在课表上 b 门 · 排课表已删 c 门）—— 课码…」＋「前往课表制作 →」（带着学期跳过去）。所有角色都看得到，主任改完排课表当下就会出现。
  - 不显示：没选学期、该学期没有存档、完全一致。**存档当时没排上的课会一直算「不在课表上」**（存档里没有它们），直到排上并重新存档。
  - 存档来源：这次打开过课表制作的同一学期就用它手上的（存档／删除存档后是最新的），否则读一次、2 分钟内不重读；`renderSch` 结尾与切回排课表分页时重算。整段包在 try 里，出错只是不显示，不会弄坏排课表。

### 11.6 动态 MRV 实测无效（2026-11-16，别再白做一遍）
起因：Aj. Tsai 提议「动态稀缺度」优先权（`R=1/(N+1)`、`P=W×R`），另有一份第三方「课表自动排程引擎 2.0 品质导向优化方案」md 建议把排序从「静态算一次」改成 **Dynamic MRV（Minimum Remaining Values，每步挑此刻可行组合最少的先排）**。
- **做法**：`_ttRunOnce` 加 `opts.mrv` 开关（默认关＝行为不变），开时把初始排放从「照 `_k` 排一次照序塞」改成「每步在未排的课里挑 `_ttSlotOpts(...).length`（此刻可行时段数）最少的先排，平手用 `_k`」；修复/间隔/评分/48 轮不变。
- **三学期 A/B 实测（匿名只读载入线上资料）**：

  | 学期 | 现版 未排/只排1/撞堂（耗时） | MRV 未排/只排1/撞堂（耗时） |
  |---|---|---|
  | 2569-1 | 1 / 0 / 0（0.8s） | 1 / 0 / 0（5.0s） |
  | 2569-2 | 2 / 0 / 0（1.3s） | 2 / 0 / 0（4.2s） |
  | 2569-3 | 0 / 0 / 0（0.1s） | 0 / 0 / 0（0.6s） |

- **结论：结果一字不差、却慢 4~6 倍 → 不采用，原型已撤回（`git checkout` 还原，未 commit）。** 原因：现版 48 次多重启动已排得很满，剩下的未排是**硬资源墙**（2569-1 KL309：59 人要电脑室、电脑室容 45），任何排序策略都排不上，只能拆班/换教室；MRV 解的是「顺序没排好导致卡住」，而我们没卡在顺序上。
- **那份 2.0 方案**：真正新的就是 MRV 这条（实测无效）；局部搜索（Move/Swap/挪一门/改半方案）我们已有；模拟退火对 ~78 门的小规模过头。**现版求解器维持不动。** 若日后课量大增（卡在顺序而非资源）再评估。

### 11.8 评分改成分层比较（2026-11-16，已上线 `856b050`）

### 11.10 看存档时，「不在课表上」的课也列出原因与建议（主任看得到）（2026-11-17，已上线 `856b050`）
起因（Aj. Tsai 截图）：主任看 2569-2 存档 v3，橘色框只写「排课表新增 4 门（KB222、KL302、KL308、KF311）」，看不到为什么没排上，没有依据去调整排课表。原因：存档只存「排上的课」，`_ttSolutionFromSaved` 的 `unplaced` 永远是空的，所以看存档时「待处理一览」没有未排的课、没有建议。
- **改法**（`_ttNotOnSaved(sem,sol)`，由 `_ttSolutionFromSaved` 呼叫）：排课表里有、存档课表上没有的课（存档当时没排上，或存档后排课表才新增；实习课除外）→ 当成「未排」放进 `sol.unplaced`（带 `notOnSaved`）。于是看存档时：

  - **橘色框**那一行改成「不在课表上 N 门（存档时没排上，或存档后排课表才新增）」，每门一个胶囊：鼠标移上去浮出原因与建议、点了跳到未排区；并指到下方的待处理一览。
  - **可编辑角色**：这些课出现在未排区，可以直接拖进课表（原本「新增的课拖不到」）；「🧩 只补排」照旧。
